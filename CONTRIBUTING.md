# Contributing to tinylm

Thanks for your interest! Bug reports, test cases, documentation fixes and training results from
other hardware are all welcome.

## Ground rules

- **Keep it honest.** Every number in the README comes from a run whose log is committed under
  `results/`. If you add a result, commit the JSON/JSONL it came from and say which machine produced it.
  Never fill a hardware table from an estimate.
- **Hand-written core.** PyTorch is used for tensors and autograd only. Please don't replace the model,
  optimiser, schedule, tokenizer, dedup or data pipeline with library calls.
- **Tests first.** Every behaviour change needs a test. Run the suite before opening a PR:
  ```bash
  python -m pytest -q tests
  ```
  The logits-parity tests need a built tinyinfer checkout (`TINYINFER_DIR=/path/to/tinyinfer`);
  they skip cleanly without one.
- **Small PRs.** One logical change per PR, with a clear description.
- **Style.** Follow `.editorconfig` (4-space indent, LF line endings, no trailing whitespace).

## Figures

The README images are generated by `docs/assets/make_figures.py` from the files in `results/`.
If your change alters a result, regenerate the figures and commit both.

## Reporting bugs and ideas

Use the issue templates. For security problems, **do not open a public issue**: see
[SECURITY.md](SECURITY.md).
